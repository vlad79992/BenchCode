## Описание Проекта

Проект **BenchCode** предназначен для создания автоматизированной веб-платформы замера, проверки и сравнительного анализа эффективности алгоритмических решений.

Процесс проверки алгоритмов часто упирается в разную мощность личных компьютеров пользователей, ручной ввод замеров в таблицы и высокую операционную нагрузку. BenchCode решает эту проблему за счет выполнения кода на едином сервере в изолированных Docker-контейнерах с вычислением медианных показателей времени и памяти, исключая необходимость сложной авторизации в MVP v1.0.

## Цели Проекта

Главная цель проекта - разработать и внедрить надежный сервис для автоматизированного изолированного исполнения и профилирования программных решений.

Платформа должна гарантировать объективность замеров ресурсов за счет расчета медианных показателей по серии прогонов, исключая случайные аппаратные скачки и фоновые лаги ОС. В рамках первой версии системы требуется обеспечить стопроцентную изоляцию и безопасность хост-сервера от вредоносного или зависающего кода, а также полностью автоматизировать процесс построения рейтинговой таблицы (Leaderboard) без необходимости ручной сборки данных.

## Контрольные Точки и Основные События

**КТ-1: Организация проектной среды и анализ требований**

Сбор и фиксация бизнес-требований, проектирование ролевой модели, пользовательских сценариев (User Stories, CJM) и утверждение Устава проекта.

**КТ-2: Проектирование сервиса (внешнее и внутреннее)**

Разработка архитектуры системы, спецификация REST API (OpenAPI), проектирование схемы базы данных PostgreSQL и схемы Docker-изоляции.

**КТ-3: Разработка и тестирование MVP**

Реализация веб-интерфейса, создание Docker-воркера для запускного движка, настройка медианного генератора метрик и проведение комплекса интеграционных и нагрузочных тестов.

**КТ-4: Демонстрация ИТ-решения и запуск пилота**

Развертывание публичного стенда, проведение апробации платформы на контрольной группе участников и подведение итогов пилотного запуска.

## Ограничения Проекта

**Входит в границы MVP:**

Переключение ролей на главной странице (Студент / Преподаватель) без формы регистраций.

Создание соревнований по Мастер-паролю с автогенерацией уникального кода.

Изолированный прогон в Docker, медианный расчет ресурсов, формирование Leaderboard.

Реестр всех сохраненных посылок для организатора/преподавателя.

**Ограничения:**

**Бюджет:** 0 рублей (отсутствие выделенного бюджета, использование имеющейся серверной инфраструктуры).

**Команда:** Разработка ведется строго силами 3 человек (PM/Аналитик, Архитектор, QA).

**Платформа:** Только адаптивное Веб-приложение.

## Регламент взаимодействия и принятие решений

**Принятие решений:**

По организационным вопросам и срокам - окончательное слово за Тимлидом.

По архитектуре и коду - за Главным архитектором.

По приемке функционала и качеству - за Главным тестировщиком.

**Разрешение конфликтов:** В случае разногласий проводится голосование.
