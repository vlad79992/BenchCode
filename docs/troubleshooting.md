# Решение проблем

## Kotlin Toolchain не загружается

При первом запуске `kotlin` / `kotlin.bat` wrapper скачивает закреплённый CLI и JRE. Проверьте соединение с `packages.jetbrains.team`, доступность диска для локального кеша и повторите исходную команду. Если скачивание прервалось, wrapper не считает неполный архив успешно установленным; после устранения сетевой проблемы запустите команду ещё раз.

Не меняйте версию или SHA-256 только для обхода сбоя: оба значения должны соответствовать одному проверенному дистрибутиву и синхронно обновляться в `kotlin` и `kotlin.bat`.

## Amper сообщает об отсутствующих зависимостях или модуле

- Запускайте команды из `BenchCode.ComposeWebApp` либо из каталога его модуля.
- Проверьте написание имени модуля в `-m` и наличие модуля в `project.yaml`.
- Убедитесь, что изменения зависимостей внесены в нужный `module.yaml`, а версии библиотек определены в `libs.versions.toml`.
- При проблеме резолвинга проверьте прокси/доступ к репозиториям Maven и повторите `kotlin build`.

## Не собирается Android target

Проверьте Android SDK, выбранный SDK path в IDE/окружении и установленные platform/build-tools. Для Android также нужны необходимые лицензии SDK. Ошибка только в Android target не обязательно означает ошибку общих или Wasm исходников; проверьте отдельно нужные модули/targets после настройки SDK.

## Desktop не запускается

Убедитесь, что установлен совместимый Java runtime, затем повторите `kotlin build -m desktopApp` и `kotlin run -m desktopApp`. Ошибки подключения к display-серверу могут быть вызваны headless Linux или удалённой сессией, а не компиляцией Kotlin.

## Web/Wasm не запускается или страница пустая

Сначала проверьте отдельную сборку и запуск:

```shell
./kotlin build -m webApp
./kotlin run -m webApp
```

Откройте URL, напечатанный CLI, и проверьте консоль браузера. Для Aspire-сценария дополнительно убедитесь, что работает Docker Engine: AppHost строит Wasm frontend в Linux-контейнере. Если `BenchCode.Web` показывает пустую страницу, проверьте наличие собранных файлов в `BenchCode.Web/wwwroot` после экспортного шага.

## DataStore не сохраняет данные между запусками

Платформы используют разные места хранения: Android app files, JVM system temp directory, Web Local Storage. Для браузера проверьте origin и настройки хранения сайта; для JVM проверьте файлы в системном временном каталоге. Удаление данных приложения/сайта, смена origin или очистка temp-каталога удаляет локальное состояние.

## Dokka CLI завершился с ошибкой

- Проверьте `java -version` (используйте JDK 21) и наличие Maven.
- Из корня запустите `pwsh -File docs/scripts/build-kotlin-api.ps1`, чтобы Maven восстановил закреплённые CLI и HTML-зависимости из `dokka/pom.xml`.
- Убедитесь, что source roots в `dokka/dokka.json` существуют. Платформенные каталоги называются `src@android`, `src@jvm`, `src@wasmJs`.
- Читайте первое сообщение Dokka о parsing/analysis: сообщения о неразрешённых типах сторонних библиотек относятся к отсутствующему compile classpath; проверьте, завершилась ли генерация и появился ли `.dokka/kotlin-api/index.html`.

## DocFX не видит Dokka страницы

DocFX берёт статические файлы из `.dokka/kotlin-api/`, поэтому сначала выполните Dokka-скрипт и проверьте наличие `index.html`. Затем запускайте `dotnet tool run docfx build docfx.json` из корня репозитория; для `dotnet tool restore` требуется .NET SDK 10.

## Полная интеграция Aspire не запускается

Из корня проверьте `dotnet --list-sdks`, доступность Docker daemon и выполните:

```shell
dotnet run --project BenchCode.AppHost/BenchCode.AppHost.csproj
```

Kotlin wrapper сам по себе не запускает Aspire, а `dotnet run` здесь нужен только для полного сценария, где Wasm-файлы собираются в контейнере и обслуживаются `BenchCode.Web`.
